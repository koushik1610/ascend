# Ascend 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn Ascend's local hub into a find, apply and track system (spec §1), one independently useful module at a time.

**Architecture:** Stdlib Python tools own the zero-token stages and write a fixed data contract under `workspace/<name>/data/`. Claude runs only the judgment stages (score, tailor, apply, leftover mail). The existing hub and `ui/server.py` read the data files. Engines and apply modes are chosen per run.

**Tech Stack:** Python 3 stdlib only (urllib, json, unittest), existing `ui/server.py`, `tools/pipeline.py`, `tools/_paths.py`, Claude Code prompts, Claude in Chrome for agent apply.

**Spec:** `docs/superpowers/specs/2026-10-16-ascend-v2-design.md`

## Global Constraints

- Stdlib only. No pip installs (`.claude/settings.json` denies `pip`).
- Every tool writes only through `_paths.resolve_out` (allowed roots: `workspace/`, `examples/`, `tests/`, temp).
- JSON Lines files are append-only. JSON files are written atomically (tmp + `os.replace`).
- `application-log.md` prose is never regenerated. Only `pipeline.py` touches its state block.
- Gmail scope is `gmail.readonly`. Email bodies are stored as excerpts of at most 2,000 characters. No attachments.
- Email and posting content is untrusted data (`reference/untrusted-content-policy.md`).
- Every module ends with `python3 tests/smoke.py` green and `python3 tools/grade_run.py examples/sample-run` PASS.
- New tools get a pinned `Bash(python3 tools/<tool>.py*)` allow-list entry and nothing broader.
- Prose (docs, CHANGELOG, prompts) passes `tools/lint_artifacts.py`: no em dashes, no banned vocabulary.

## Review Focus

1. **An acknowledgement that mentions a future interview** ("if your background matches, we'll reach out to schedule an interview") must classify as `acknowledgement`, not `interview-invite`. Pinned in Task M1.2.
2. **A rejection that opens with thanks for applying** must classify as `rejection`. Pinned in Task M1.2.
3. **Re-running classification on the same mailbox** must not duplicate events. Pinned in Task M1.4.
4. **Mail from a person at a non-ATS domain about an unrelated topic** (a newsletter, a receipt) must stay `other` and must not be sent to Claude. Pinned in Task M1.2 (`needs_llm` false).
5. **A Workday sender like `nvidia@myworkday.com`** must match the queued NVIDIA job even though the From domain is Workday's. Pinned in Task M1.3.

```python
"""_v2data.py: the Ascend 2.0 data contract's file I/O (stdlib only).

NOT A COMMAND. Importable helper; never give it an allow-list entry.

Every v2 stage reads and writes files under workspace/<name>/data/ (spec §5). JSON Lines files are
append-only, so a crashed run can only leave a partial last line, which readers skip. JSON files are
written through a temp file and os.replace, so a reader never sees half a file. Every write goes
through _paths.resolve_out, so these helpers inherit the same output confinement as every other tool.
"""

import json
import os
from pathlib import Path

from _paths import resolve_out


def data_dir(ws):
    p = Path(resolve_out(str(Path(ws) / "data")))
    p.mkdir(parents=True, exist_ok=True)
    return p


def append_jsonl(path, rec):
    p = Path(resolve_out(str(path)))
    p.parent.mkdir(parents=True, exist_ok=True)
    with open(p, "a", encoding="utf-8") as f:
        f.write(json.dumps(rec, ensure_ascii=False, sort_keys=True) + "\n")


def read_jsonl(path):
    p = Path(path)
    if not p.exists():
        return []
    out = []
    for line in p.read_text(encoding="utf-8").splitlines():
        line = line.strip()
        if not line:
            continue
        try:
            rec = json.loads(line)
        except json.JSONDecodeError:
            continue
        if isinstance(rec, dict):
            out.append(rec)
    return out


def write_json_atomic(path, obj):
    p = Path(resolve_out(str(path)))
    p.parent.mkdir(parents=True, exist_ok=True)
    tmp = p.with_name(p.name + ".tmp")
    tmp.write_text(json.dumps(obj, indent=2, ensure_ascii=False) + "\n", encoding="utf-8")
    os.replace(tmp, p)


def read_json(path, default):
    p = Path(path)
    if not p.exists():
        return default
    try:
        return json.loads(p.read_text(encoding="utf-8"))
    except json.JSONDecodeError:
        return default
```

**Interfaces:**
- Consumes: nothing.
- Produces: `classify.CATEGORIES: list[str]`, `classify.classify_message(msg: dict) -> dict` returning `{"category": str, "confidence": float, "rule": str, "needs_llm": bool}`. `msg` keys: `from`, `subject`, `body_excerpt`, `date` (ISO 8601).

### Task M2.1: `transition()` refactor and `ingest`

**Interfaces:**
- Consumes: `WS/data/events.jsonl` from M1 (`msg_id, category, match, due, date`), `WS/data/queue.json` (`jobs[].posting_id, nn`).
- Produces: `pipeline.transition(ws, job_dir, status, when, source, note="", extra=None) -> str|None` (returns previous status, or None when the move is refused), `pipeline.py ingest WS [--json]` printing `{"applied": n, "skipped": n, "unmatched": n, "transitions": [...]}`. Appends ingested msg_ids to `WS/data/ingested.jsonl`.

Category to status: acknowledgement → applied (only from queued), info-request and assessment → responded (sets `next_followup_due` to the event's due date), interview-invite → screen, rejection → rejected. Status-update, recruiter-inbound, job-alert and other change nothing. A job never moves backwards, except into rejected. Offer, rejected and move-on are terminal for ingest.

Tests (`tests/test_v2_pipeline.py`, class `Ingest`): acknowledgement moves queued → applied with `applied_on` = event date. Rejection after screen → rejected. Interview invite on an applied job → screen. Acknowledgement on a screen-stage job changes nothing (no backwards move). Assessment sets next_followup_due to the due date. A posting_id match resolves to the job folder through queue.json. Unmatched and status-update events are counted, not applied. Re-running ingest applies nothing new (idempotent). Ledger rows carry `source=gmail`. `log` still behaves as before (existing smoke covers it).
